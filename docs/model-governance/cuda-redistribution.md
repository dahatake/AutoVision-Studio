# LIC-03 — CUDA/cuDNN 非同梱判断と限定ファイル名検査

**判断記録 `LIC03-NONBUNDLE`（2026-09-13）**: 直接依存 A-05、[依存方針 §8](../dependency-policy.md#8-ネイティブバイナリと-cuda--cudnn)、[C0-PYTHON §1/3/5/8](../dependency-adoption/python-phase-c.md)、[ADR-0003 §2.2/12](../adr/0003-packaging.md) に従い、既決定の CUDA/cuDNN **非同梱**を機械検査する。NVIDIA allowlist は空（0件）。C0 の Windows 採用は公式 CPU index の `torch==2.11.0+cpu` / `torchvision==0.26.0+cpu` と `onnxruntime-directml==1.24.4`、CUDA/NVIDIA/cuDNN package 名 0 件である。今回その依存を再採用・再取得せず、モデル承認、EULA 承認、CUDA の将来採用設定を追加しない。

- **一次資料**: [CUDA Toolkit EULA / Supplement Attachment A](https://docs.nvidia.com/cuda/eula/index.html#attachment-a) は版・architecture を含む redistributable 名と配布条件を示し、[cuDNN Software License Agreement / Supplement](https://docs.nvidia.com/deeplearning/cudnn/backend/latest/reference/eula.html) は runtime `.dll` / `.so` の配布を条件付きで扱う。親調査取得日 2026-09-12、本文再取得・確認日 2026-09-13。これらは検出名と境界の根拠であって、全 EULA の一般承認、CUDA 採用、法的助言ではない。今回の根拠はこの非同梱判断記録であり、未採用版の EULA hash・承認者・承認日を捏造しない。
- **CLI**: repository root で `ml\.venv\Scripts\python.exe -B scripts\licenses\verify-cuda-payload.py C:\absolute\expanded-payload`。引数は静止した展開済み Windows ローカル directory の絶対パス1個だけ。出力は標準出力の JSON、正常時も `status=LIMITED` / exit 0、禁止名があれば `FAIL` / exit 1、不明・検査不能は `BLOCKED` / exit 2。常に `scope=cuda-nonbundling-filenames`、`nativeComponentAuditComplete=false`。ファイル件数、相対パス、サイズ、raw bytes SHA-256、hardlink 数を記録する。`manifestSha256` はパス順の `files` 配列を `ensure_ascii=True, sort_keys=True, separators=(",", ":")` で JSON 化した UTF-8 bytes の SHA-256（payload全体の署名ではない）。
- **拒否対象**: cublas/cudart/cudnn/cufft/cufftw/curand/cusolver/cusparse、nppc/nppi/npps、nvblas/nvrtc/nvvm/nvJitLink（lib prefix含む）/nvjpeg/nvToolsExt/cupti/nvcuda/nvidia、torch_cuda/c10_cuda、ORT CUDA/TensorRT providers、nvinfer/nvonnxparser 等の runtime/developer binary 名を大小文字無視で照合する。`.dll/.exe/.pyd/.node/.lib/.a/.so`（数値版suffix含む）`/.dylib/.bc/.obj/.o/.sys/.pdb`、nvcc/ptxas 等の compiler/tool、任意名の `.ptx/.cubin/.fatbin` を含む。`torch/cuda/*.py`、bytecode、header、LICENSE/NOTICE 内の CUDA 語は同梱違反としない。これら source/通知の別ライセンス審査を免除する意味でもない。
- **入力境界**: 欠損、fileをroot指定、ファイルなし・総bytes 0、空native file、不正名（ADS、予約名、dot component等）、UNC/device/drive-relative/remote path、root/祖先/子の symlink・junction・その他 reparse、offline・特殊file、読取失敗は拒否する。普通の hardlink は一律拒否せず、全パスを個別に検査・hash記録する。root込み100,000 entries、root以下64 components、1 file 8 GiB、合計64 GiB、読取り1 MiB単位、協調的300秒上限。OS I/O自体の強制中断保証ではない。変更の前後照合は行うが、敵対的な並行書換えへの原子的 snapshot/TOCTOU 保証はないため、入力を静止・アクセス制御して使う。
- **未展開物**: ZIP/WHL/PYZ/ASAR/PAK/MSI/MSIX/CAB/TAR/7z等の既知suffix、ZIP/gzip/7z/RAR等の先頭signatureやTAR headerを検出したら内容に関係なく拒否する。検査器は展開・削除・変更・実行・import・downloadをしない。PKG担当が別工程で内部まで展開したtreeを用意する必要があり、PyInstallerの`base_library.zip`も例外許可しない。一般の`.a/.lib`はnative libraryとして名前検査するだけで、内部memberは解析しない。任意に改名・偽装されたcontainerや自己展開EXE内部を完全検出するとは主張しない。
- **保証と残作業**: CPU fallback で全機能を利用可能にするのは FR-INS-006 / ADR-0003 の**規範的保証・必須条件**である。C0 の Torch CPU 加算・ORT CPU Add smoke は限定実測で、`probe_hardware` は `executionStatus=not_checked` の観測にすぎない。本leafは非同梱判断とscannerを実装するだけで、全機能・採用モデル・clean Windows のCPU fallbackおよび実 PKG-02/PKG-14 payload適用は **NOT_RUN**。ファイル名だけでは改名されたCUDA、静的リンク、native内包コード、未知部品のライセンス適合を証明できない。**LIC-01/PKG-14 の全component inventory・source/version・SBOM・payload hash対応との併用が必須**で、SEC-08 native監査やrelease Goの代替にはしない。scannerのfixture/CLI testはハードウェア動作の証拠ではなく、親の独立レビュー後にleaf完了を判定する。
