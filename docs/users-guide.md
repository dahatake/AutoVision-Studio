## 1. 本書の対象と製品の利用可否

> **機能状態:** 検証待ち
>
> **文書成熟度:** 要求反映済み
>
> **根拠:** 要求定義 §2〜§4、DOCS-102
>
> **最終化条件:** Gate 4 と Windows の DOCS-401、DOCS-403〜406 の実測 evidence

この章の `検証待ち` は、診断を含む利用者向け初回フロー全体を指します。Electron lifecycle、secure window、navigation shellに加え、限定的なProject・診断IPCとPreload API、Projectの作成・一覧・設定更新・移動／復旧のbackendにはsourceと対象testがあります。取込結果のDB保存、annotation、学習・推論までを接続した製品フローの完成を意味しません。現在の接続・実行証拠と未完了範囲は[UI/Core実行記録](ui-ux-execution.md)と[開発ガイド](developer-guide.md)を参照してください。

> **この節は実装完了後に実測内容で更新します。現時点は要求定義からの抜粋です。**

AutoVision Studio は次の処理をローカル端末内で完結します。

- **画像分類（Image Classification）** — 画像 1 枚に対し、定義したクラスのうち正確に 1 つを割り当てます（single-label multi-class）。
- **物体検出（Object Detection）** — 画像内の物体に axis-aligned の矩形（bounding box）とクラスを割り当てます（multi-class）。

### MVP に含まれるもの

以下は実装対象の機能です（要求定義 §3.1 参照）。

- 複数 Project の作成・管理
- ローカルファイル・フォルダーからの教師データ取り込み
- 画面上での分類ラベルおよび検出矩形の作成・編集・確認
- 既存モデルによる補助候補の生成と人による確認
- バックグラウンド自動学習（AutoML・ハイパーパラメーター探索）
- 学習履歴・モデル版管理・評価レポート
- 既存モデル版を起点とした追加学習
- Windows PC カメラへのリアルタイム推論
- 完全オフライン動作
- Windows 11 24H2 以降 x64 用の自己完結型インストーラー

### MVP に含まれないもの

以下は Version 1 の対象外です（要求定義 §3.2 参照）。

- Cloud サービスとの連携、外部ストレージ、テレメトリ
- ユーザーアカウント・組織管理・共同編集
- 手動でのハイパーパラメーター入力
- 動画ファイル・ネットワークカメラ・RTSP ストリーム
- セグメンテーション・姿勢推定・OCR・生成 AI
- 分散学習・複数 PC をまたぐ学習
- macOS 向けアプリケーション、MPS / CoreML 対応、カメラ権限試験、PKG、署名、notarization、servicing

### Project を作成する

1. **Project 一覧**画面で **［Project を作成］** を押します。
2. **［親フォルダーを選択］** を押すと Windows 標準のフォルダー選択ダイアログが開きます。フォルダーを選ぶと、その下に表示が切り替わります。
   - 画面には「選択した親の中にUUIDの専用フォルダーを作成します。」と表示されます。**選んだフォルダー自体が Project フォルダーになるのではありません。**
   - 選択せずにダイアログを閉じると「フォルダーの選択をキャンセルしました。」と表示され、作成は進みません。
3. **［名前（必須）］** に Project 名を入力します。
4. **［タスク種別］** で **画像分類** または **物体検出** を選びます。
5. 説明を入れる場合は **［説明を編集（任意）］** を押し、**［説明（任意）］** に入力してから戻ります。
6. **［作成］** を押します。作成に成功すると、その Project の作業画面が開きます（画面上部の見出しが Project 名になります）。
7. 作成をやめる場合は **［キャンセル］** を押します。

> 送信後に **［作成］** の結果を確認できない場合、画面は「作成結果を確認できません。一覧で状態を確認してください。」と表示します。このときは**作成をやり直さず**、一覧で結果を確認してください。

### Project 一覧で確認する

**［Project 一覧に戻る］** で一覧へ戻ります。一覧の各行には次が表示されます。

| 表示項目 | 現在の内容 |
|---|---|
| Project 名 | 長い名前は「… 全文」から全文をページ送りで確認できます |
| タスク種別 | 画像分類 / 物体検出 |
| 最終更新日時 | 端末のロケール表記 |
| 最新Run状態 | **未取得**（本 version では取得しません） |
| 選択モデル | **未取得**（同上） |
| 使用容量 | **未取得**（同上） |

- **［名前・説明を検索］** に文字を入れると、名前と説明で絞り込みます。
- **［再取得］** で一覧を取り直します。取得に失敗した場合はボタンが **［再試行］** になり、直前の一覧は「前回の一覧（最新ではありません）」と明示されます。
- 件数が多い場合は **［最初］［前へ］［次へ］［最後］** でページを移動します。
- 各行の **［開く］** で作業画面へ、**［設定］** で Project 設定へ移動します。

作成した Project は、アプリを終了して再起動しても一覧に残ります。ほかの Project の内容は変更されません。

### Project を削除する

1. 一覧で対象行の **［削除対象を確認］** を押します。削除前の確認ダイアログが開きます。
2. ダイアログには次が分けて表示されます。
   - **削除される所有データ** — Project フォルダー（件数・容量）、取り込み（Copy）、Copy済み画像、Label Schema、Annotation Workspace、Annotation 画像、Dataset Revision、Dataset 画像、Training Run、その他の処理履歴。
   - **削除されない参照データ** — 「Reference で取り込んだ元ファイルは削除・変更しません。」と明記され、取り込み（Reference）件数と参照元画像の件数・容量が表示されます。
   - 本 version で件数を取得できない項目（Model Suggestion、Model Version、レポート、派生キャッシュ）は「未実装のため件数を取得できない項目」として名前だけが示されます。**0 件とは表示しません。**
   - フォルダーを測定できなかった場合は「フォルダーが見つかりません（容量は不明）」「フォルダーを読み取れません（容量は不明）」と表示されます。
3. 削除できない理由がある場合は、その一覧が表示され **［削除する］** は押せません。
4. **［上記の所有データを削除することを確認しました。］** にチェックを入れると **［削除する］** が有効になります。**チェックなしでは削除できません。**
5. **［削除する］** を押すと削除され、「Project「〈名前〉」を削除しました。参照元ファイルは削除していません。」と表示されます。一部の所有ファイルを削除できなかった場合は、その件数が続けて表示されます。
6. やめる場合は **［キャンセル］** を押します。

- Project 設定画面からの名前・説明の保存、保存場所の変更（移動）は実装されていますが、本書では手順を実測していません。手順は実測後に追記します。

## 7. Copy / Reference、入力形式、データ権利

> **機能状態:** 実装済み
>
> **文書成熟度:** 実測済み
>
> **根拠:** FR-DAT-001〜016、FR-LIC-009、ADR-0002。手順は `tests/e2e/import-classification.spec.ts` / `tests/e2e/import-detection.spec.ts` の実行で再現（署名前ビルド、Windows 11 24H2 x64）
>
> **最終化条件:** 保存先の空き容量不足時の表示（未実測）、署名済み package での OS 標準ダイアログ実機確認、OS 再起動をまたいだ Reference アクセスの実機確認

### 7.1 対応形式

**対応画像形式：** JPEG、PNG、WebP、BMP、TIFF

- 拡張子だけでなく画像の実体を検証します。壊れたファイルは検査結果の「問題一覧」に報告され、**黙って除外されません**。
- アニメーション画像は非対応です（先頭フレームのみの暗黙利用は行いません）。
- EXIF Orientation を反映した向きで表示・学習します。元ファイルは変更しません。

**アノテーション形式：** 取り込み画面では、Project のタスク種別に応じた形式だけが選べます。

| タスク種別 | 選べるデータ形式 | 選択するもの |
|---|---|---|
| 画像分類 | **クラス別フォルダー** | 画像フォルダー（直下のフォルダー名がクラス名） |
| 画像分類 | **CSV ラベル** | 画像フォルダー → 続けて `path,label` の UTF-8 CSV |
| 画像分類 | **ラベルなし・フォルダー** | 画像フォルダー |
| 画像分類 | **ラベルなし・画像ファイル** | 画像ファイル（複数選択可） |
| 物体検出 | **COCO アノテーション** | 画像フォルダー → 続けて COCO JSON |
| 物体検出 | **ラベルなし・フォルダー** / **ラベルなし・画像ファイル** | 同上 |

CSV は `path,label` の見出し行が必要で、`path` はフォルダーからの相対パスです。COCO JSON では、存在しない画像 ID・未定義のカテゴリ ID・画像の外にはみ出す bounding box が、それぞれ「問題一覧」に個別に報告されます。

取り込み時の検証エラーが 1 件でもある場合は、学習を自動開始しません（FR-DAT-008）。

### 7.2 取り込みの手順

1. Project の作業画面で **［取り込む］** タブを開きます。見出しは「画像を取り込む」です。
2. **［データ形式（必須）］** から形式を 1 つ選びます。
3. **［取り込み方法（必須）］** から **コピー（推奨）** または **参照** を選びます。
   - 画面には「コピーは画像をプロジェクト内へ保存します。参照は元の画像を使用するため、移動・削除しないでください。方法は必ず選択してください。」と表示されます。
4. **［データを選択して検査］** を押します。Windows 標準のダイアログが開きます。CSV ラベルと COCO アノテーションでは、**フォルダー → 注釈ファイル**の順に 2 回開きます。
   - 選択せずに閉じると「選択をキャンセルしました。」と表示され、**検査は始まりません**。
5. 検査が終わると「2. 検査結果を確認して取り込む」が表示されます。画像件数・合計バイト数・クラス件数・エラー件数・警告件数、クラス名の一覧、ファイル名の一覧、問題一覧を確認します。
   - クラス名は取り込み前に変更できます。空白だけの名前は使用できません。
   - 「ラベル付きの画像も未確認として取り込みます。検査の完了は、画像の確認済み・学習完了を意味しません。」と明示されます。
6. **［データの利用権利］** のチェックを入れます（§7.3）。**チェックするまで［取り込む］は押せません。**
7. **［取り込む］** を押すと取り込みが実行され、「結果記録」に「取り込み完了／画像は未確認です」と件数が表示されます。
8. やり直す場合は **［検査を破棄してやり直す］** を押します。

> 取り込み結果を確認できない場合、画面は「取り込み結果が不明です。状態を再確認してください。」と表示し、ボタンは **［状態を再確認］** になります。このときは**取り込みをやり直さない**でください。

### 7.3 入力データの権利確認

取り込みの確定前に、入力画像・ラベル・アノテーションを利用・学習する権利を有することを確認するチェックが必要です（FR-LIC-009）。

画面には「同梱サンプルも対象です。著作権・個人情報・利用条件を確認する責任は利用者にあります。この確認は法的な適合性を保証するものではありません。同意は取り込みと同じ処理で記録します。」と表示されます。

- アプリは法的権利を自動保証しません。
- 確認は取り込みと同じ処理で記録されます。

### 7.4 Copy モードと Reference モード

データ取り込み時に必ずどちらかを選択します（FR-DAT-002）。

この選択は Project 作成時の保存場所とは別です。Copy / Reference は取り込む元データの保持方法を決め、Project 作業フォルダーはProject所有の画像・artifact・cacheの配置先になります。共通のSQLiteメタデータDB、移動記録、migration用backupはMainが定めるapp-data（`userData`）側に別置きされ、Project作業フォルダーの変更では移動しません。Projectフォルダーだけのコピーを完全なバックアップとみなさないでください。

| モード | 概要 | 注意点 |
|---|---|---|
| **コピー（推奨）** | 元画像を Project 作業領域へ複製して使用する | 元ファイルと同等の容量が Project 領域に追加されます |
| **参照** | 元ファイルを複製せず、絶対パスと内容ハッシュを参照する | ファイルが移動・変更・削除された場合は再リンクが必要です |

保存先の空き容量が不足する場合は取り込みを中止し、必要バイト数と利用可能バイト数を表示します。**この表示は本書では実測していません。**

### 7.5 参照元の確認と再リンク

参照（Reference）で取り込んだ元ファイルは Project の外にあります。移動・削除されると使えなくなります。

1. **［教師データ］** タブの **「参照元（Reference）の確認」** で **［参照元を確認］** を押します。
2. すべて確認できた場合は「参照元 〈件数〉 件すべてを確認できました。」と表示されます。
3. 確認できないものがある場合は件数が表示され、「確認できない参照元」の一覧に**画像キーと理由**（元のファイルが見つかりません／開けません／内容が変わっています など）が出ます。
4. 各行の **［参照元を選び直す］** を押すと Windows 標準のファイル選択が開きます。
   - **元とサイズ・内容（SHA-256）が一致するファイルだけ**が受け入れられます。
   - 異なるファイルを選ぶと「選んだファイルは元の内容と一致しません（サイズまたは内容が異なります）。同じファイルを選び直してください。」と表示され、**参照は変更されません**。
   - 選択をキャンセルすると「選び直しをキャンセルしました。」と表示されます。
5. 復旧すると「参照元を選び直しました。」と表示され、再確認で件数が減ります。

**Reference モードの注意事項（FR-DAT-012、FR-DAT-013）：**

- 参照元ファイルが継続してアクセスできない場合は再リンクを求めます。
- Training Run 開始直前と学習中に全ファイルのハッシュ検証を行います。変更・消失が 1 件でもあれば Run を開始しないか安全に停止します。

### 各画像の状態

取り込み後の画像は次の状態で管理されます（FR-ANN-005）。

| 状態 | 説明 |
|---|---|
| 未着手 | ラベルも補助候補もない |
| 補助候補あり | 補助モデルが候補を生成済み、未確認 |
| 編集中 | ユーザーが編集を開始している |
| 確認済み | ユーザーが明示的に確定操作を行った |
| 除外 | 学習・評価 split に含めない |

**「確認済み」の画像のみが教師データになります。** 未確認の画像は Dataset Revision に含まれません（FR-ANN-011）。

### 確認時の検証

Dataset Revision 確定前に次の項目が検証されます（FR-ANN-011）。

- 0 件クラスまたは複数クラスが割り当てられた画像（エラー）
- Label Schema 外のクラス（エラー）
- 未処理の補助候補
- クラスごとの件数と偏り

エラーが 1 件でもある場合は確定できません。

### 取り込みから学習 Queue までの操作手順

以下は `tests/e2e/annotation-detection.spec.ts` の実行で再現した手順です（署名前ビルド、Windows 11 24H2 x64）。**学習の実行そのものは本 version では未実装**で、Queue へ渡すところまでが対象です。

1. 物体検出の Project を作成し、**［取り込む］** タブで **COCO アノテーション** などを取り込みます（[§7](#7-copy--reference入力形式データ権利)）。
2. **［教師データ］** タブを開き、「画像一覧」から画像を選びます。
3. **「検出キャンバス」** が開きます。
   - 上部に **「作業指示」** が常時表示されます。
   - **［拡大］［縮小］［全体表示］** で表示倍率を変えられます。画像表示領域にフォーカスがある状態では、**矢印キー**で移動、**＋ / −** で拡大縮小できます。
   - 現在の状態は「表示倍率 〈％〉 ／ 表示位置 X 〈値〉, Y 〈値〉」として表示されます。
   - これ以上拡大・縮小・移動できない場合は、**現在の表示を保ったまま**その旨が表示されます（勝手に限界値へ吸着しません）。
4. **［新規領域のクラス］** で、これから描く矩形に割り当てるクラスを選びます。
5. **画像の上をドラッグ**して矩形を作成します。
   - 矩形は画像の内側に収まるよう調整されます。**画像の外で指を離すと矩形は作成されません。**
   - 小さすぎる矩形（誤クリック相当）は作成されません。
6. 作成した矩形は **「領域一覧」** に「領域 N（X …, Y …, 幅 …, 高さ …）」として並びます。
   - 行の **［領域 N（…）］** を押すと画像上の矩形が選択されます。
   - **［領域 N のクラス］** で矩形ごとのクラスを変更できます。
   - 選択中の矩形は画像上に「選択中 〈ID〉」と表示され、右上の **×** で削除できます。
   - 選択中の矩形は、ハンドルのドラッグで移動・サイズ変更できます。座標は**元画像のピクセル**で保存されます。
7. 矩形を作り終えたら **［確認済みにする］** を押します。領域が 1 件もない場合、このボタンは押せません。
8. **対象物が写っていない画像**は、「対象物なしの確認」で区別します。
   - まだ誰も見ていない画像は「未着手（対象物なしの確認はされていません）」と表示されます。**未着手と「対象物なし」は別物です。**
   - **［対象物なしとして確定］** を押すと「対象物なし（確認済み）」になります。
   - 領域が残っている場合は「領域 〈件数〉件（対象物なしにはできません）」と表示され、押せません。「領域をすべて削除すると「対象物なし」として確定できます。」と案内されます。
9. すべての画像について 3〜8 を行い、**「表示分の未確認 0 件」** を確認します。
10. **［Dataset を確定する］** →（内容確認）→ **［確定して学習 Queue へ渡す］** を押します。確定すると「Dataset Revision 〈番号〉 を確定しました。学習ジョブ 〈ID〉 は Queued です。」と表示されます。

### 制約事項（FR-ANN-205）

- 矩形は画像の境界内に clamp されます。
- 幅・高さが 0、NaN、負値、画像外のみの矩形は拒否されます。

### 対象物がない画像

対象物が存在しない画像は「対象物なし」と明示確認できます（FR-ANN-206）。未着手とは区別され、negative sample として Dataset Revision に含まれます。

### COCO フォーマットの取り込みと編集

取り込んだ COCO の bounding box と category を同じエディターで修正できます（FR-ANN-209）。確定 manifest の保存表現は COCO の `[x, y, width, height]` の意味論へ lossless に変換でき、provenance（`import-unmodified` / `import-edited`）が記録されます。元 JSON の byte-for-byte round-trip や再 export の UI を保証する記述ではありません。

矩形の複製・全選択・keyboard shortcut、および同一クラスの高重複の警告は実装されていますが、本書では手順を実測していません。手順は実測後に追記します。**重複した矩形が自動削除・自動統合されることはありません。**

補助候補（Model Suggestion）は、既存モデルが生成したラベル名・分類ラベル・矩形の候補です。**人が確認するまで Ground Truth にはなりません。**

### 補助に使用するモデル

- 同一 Project に成功済み Model Version がある場合、最新成功版が既定で選択されます（FR-AST-002）。

インストーラーに同梱するモデルは、ライセンス・データ由来・用途・品質の審査を通過したものだけです。現時点で同梱を承認済みの補助モデルはありません。審査前のモデルを同梱した状態では本機能は出荷されません。

- 補助候補は Ground Truth（確定済みアノテーション）と異なる色・線種・バッジで表示されます（FR-AST-009）。

### ユーザーの操作（実装完了後に手順を記載予定）

各候補を個別に次のいずれかで処理します（FR-AST-010）。

- **承認** — 候補を draft アノテーションにコピーする（画像全体の「確認済み」にはなりません）
- **編集して承認** — 内容を修正してから draft アノテーションにコピーする
- **却下** — 候補を使用しない

**全候補の処理と画像単位の確定操作を完了した画像だけが「確認済み」になります。**

### 自動承認はありません

高スコアでも自動承認・一括承認は提供しません（FR-AST-011）。補助候補の承認のみでは「確認済み」にならず、見逃しがないかをユーザーが確認する操作が必要です。

### 学習の開始

Dataset Revision を確定すると、追加のハイパーパラメーター入力を求めずに Training Run が自動登録されます（FR-TRN-001）。学習は UI とは別のプロセスで実行され、学習中も Project の閲覧・画面遷移が可能です（FR-TRN-002）。

### Training Run の状態

| 状態 | 説明 |
|---|---|
| Queued | 実行待ち（FIFO） |
| Preparing | 準備中 |
| Running | 学習中 |
| Exporting | ONNX 変換中 |
| Evaluating | 評価中 |
| Succeeded | 完了（Model Version が作成されます） |
| Failed | 失敗（ログ・Trial は保持） |
| Cancelled | キャンセル済み（再開不可） |
| Interrupted | 中断（条件一致時に再開可能） |

Model Version は `Succeeded` のときのみ作成されます。

### 実行の制約

- 1 台の端末で同時に実行される Training Run は原則 1 件で、他は FIFO Queue に置かれます（FR-TRN-010）。
- Queued 状態の Run を削除できます。
- 実行中の Run をキャンセルできます。キャンセル後は再開できません（FR-TRN-013）。
- アプリまたは OS の異常終了後、条件が一致する場合のみ中断 Run を再開できます（FR-TRN-014）。

### 学習時間について

学習時間はデータ件数・画像解像度・クラス数・ハードウェアに依存します（要求定義 §6.2）。固定の学習時間は保証されません。ノート PC で長時間学習する場合は電源接続と十分な冷却を推奨します。

### プライバシーに関する重要事項

- カメラフレームおよび推論結果は**既定でディスクに保存されません**（FR-INF-017）。
- ログにも画像の内容は保存されません（FR-INF-017）。
- カメラフレームは端末外に送信されません（FR-SEC-001）。

### カメラ権限の要求タイミング

カメラ権限は、**ユーザーが推論開始操作をした時だけ**要求します（FR-INF-003）。起動時・Project 閲覧時・インストール時には要求しません（FR-INS-014）。

OS の権限要求の前に、利用目的・保存有無・停止方法をアプリ内で説明し、ユーザーの明示同意を得ます（FR-INF-004）。

### 主な操作（実装完了後に手順を記載予定）

- 推論対象モデル版の選択（同一 Project の成功済み版から）
- カメラの選択（複数ある場合）
- 推論の開始・停止
- 信頼度しきい値・表示設定の保存（Inference Profile、FR-INF-014）

Inference Profile は Project ごとの推論設定です。端末診断、データ取り込み、Label Schema とは別の lifecycle を持ちます。保存場所、既定値、編集画面名は実装・実測後に確定します。

### 性能について

- 推奨ハードウェアと承認済み軽量モデルでは、30 分連続試験で FR-INF-010 / NFR-PERF-004 の service time、capture-to-display p95、10 Hz 全フレーム処理、drop 0 を満たすことが**出荷条件**です。
- 端末が 100 ms を超える場合は最新フレーム優先で継続し、実 FPS・レイテンシ・drop 数・性能警告を表示します（FR-INF-011）。

### 学習と推論のリソース競合

同じアクセラレーターで学習が実行中の場合、推論開始前に警告が表示されます。学習の中断または CPU での推論のいずれかを選択できます（FR-INF-019）。

### 学習が失敗する場合

- データ取り込み前に、元データ・予測生成物・一時領域・安全余裕（20%）を含む必要容量を計算します（NFR-STO-001）。容量不足の場合は開始しません。
- キャッシュや失敗 Run の一時 checkpoint を選択削除する設計です。操作と回復容量は未検証です。

### 診断ログの出力

ローカル診断 export はユーザーの操作時だけ生成され、含有項目が事前に表示されます（NFR-SEC-004）。ログには画像本体は含まれません（FR-SEC-010）。

**この小節の現状（2026-09-12／開発版0.1.0）：** 限定した「診断要約」の保存を接続しました。一般的な生ログの収集や、診断画面の全データの書き出しではありません。本章のほかの未実装機能や、製品全体の受入完了を意味しません。

- 設定の「端末・容量」にある「診断要約を保存」が明示的な入口です。起動・診断取得だけでは要約ファイルを作りません。保存要求時にMain側で診断を取得し直すため、表示中の観測値とは取得時点が異なる場合があります。
- 実装では、OS確認ダイアログに要約本文と保存先を表示し、「保存」の承認後だけ保存します。「キャンセル」が既定で、取消応答ではファイルを生成しません。確認画面の応答処理は自動試験で検証していますが、**OS確認画面の実描画・本人の操作・Narratorは未検証**です。
- 本文はOSの数値情報、CPU数、メモリ・ディスク容量、GPU件数、既知providerの一覧への有無、固定の取得状態などに限定します。画像、機器名、自由な版文字列、Project情報、生ログ、絶対パスは含めません。CPU動作可・推奨構成・モデル性能の判定でもありません。
- 保存先はMain管理の`userData/logs`配下の新規`diagnostics-<UUID>.txt`です。既存ファイルを上書きしません。成功時の「保存先を表示」から長いパスも全文を確認できます。**保存先の表示**にはパスが含まれますが、保存する**要約本文**には含まれません。
- 「別の診断要約を確認・保存中」は先行要求の終了待ちです。「保存結果を確認できません」は取消・未生成の証明ではなく、途中ファイルや保存済みファイルが残る場合があります。再度要求する前に保存先の状態を確認してください。アプリは失敗後の自動再送や既存ファイルの削除を行いません。
- 詳細画面から戻ること自体は、送信済みの保存要求の取消ではありません。取消は確認画面で行います。古い接続で「要約保存：利用不可」と表示される場合も、診断の取得は別の機能として利用できます。

開発版の実UI→Preload→Main→Python→ファイル保存は隔離環境で9ステップ・21画面を確認済みです。確認ダイアログの取消／承認にはテスト応答を使った限定技術検証であり、完成製品の操作手順・正式配布の合格とは扱いません。証拠と残条件は[SEC-07実行記録](ui-ux-execution.md#sec-07診断要約の明示保存限定接続2026-09-12)を参照してください。
