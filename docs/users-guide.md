## 1. 本書の対象と製品の利用可否

> **機能状態:** 検証待ち
>
> **文書成熟度:** 要求反映済み
>
> **根拠:** 要求定義 §2〜§4、DOCS-102
>
> **最終化条件:** Gate 4 と Windows の DOCS-401、DOCS-403〜406 の実測 evidence

この章の `検証待ち` は、診断を含む利用者向け初回フロー全体を指します。Electron lifecycle、secure window、Preload の `contractVersion`、navigation shell は実装済みですが、feature IPC と Project / data / annotation API は未実装です。

> **この節は実装完了後に実測内容で更新します。現時点は要求定義からの抜粋です。**

AutoVision Studio は次の処理をローカル端末内で完結します。

- **画像分類（Image Classification）** — 画像 1 枚に対し、定義したクラスのうち正確に 1 つを割り当てます（single-label multi-class）。
- **物体検出（Object Detection）** — 画像内の物体に axis-aligned の矩形（bounding box）とクラスを割り当てます（multi-class）。

### MVP に含まれるもの

以下は実装対象の機能です（要求定義 §3.1 参照）。

- 複数 Project の作成・管理
- ローカルファイル・フォルダーからの教師データ取り込み
- 画面上での分類ラベルおよび検出矩形の作成・編集・確認
- 既存モデルによる補助候補の生成と人による確認
- バックグラウンド自動学習（AutoML・ハイパーパラメーター探索）
- 学習履歴・モデル版管理・評価レポート
- 既存モデル版を起点とした追加学習
- Windows PC カメラへのリアルタイム推論
- 完全オフライン動作
- Windows 11 24H2 以降 x64 用の自己完結型インストーラー

### MVP に含まれないもの

以下は Version 1 の対象外です（要求定義 §3.2 参照）。

- Cloud サービスとの連携、外部ストレージ、テレメトリ
- ユーザーアカウント・組織管理・共同編集
- 手動でのハイパーパラメーター入力
- 動画ファイル・ネットワークカメラ・RTSP ストリーム
- セグメンテーション・姿勢推定・OCR・生成 AI
- 分散学習・複数 PC をまたぐ学習
- macOS 向けアプリケーション、MPS / CoreML 対応、カメラ権限試験、PKG、署名、notarization、servicing

>

### 7.1 対応形式

*（実装完了後に実際の検証方法と制限を記載予定）*

**対応画像形式：** JPEG、PNG、WebP、BMP、TIFF

- 拡張子だけでなく画像の実体を検証します。
- アニメーション画像は非対応です（先頭フレームのみの暗黙利用は行いません）。
- EXIF Orientation を反映した向きで表示・学習します。元ファイルは変更しません。

**アノテーション形式：**

- 画像分類：未ラベル画像、`ルート/クラス名/画像` のフォルダー構造、`path,label` を持つ UTF-8 CSV
- 物体検出：未アノテーション画像、または COCO JSON（画像・カテゴリ・bounding box）と対応する画像ルート

取り込み時の検証エラーが 1 件でもある場合は、学習を自動開始しません（FR-DAT-008）。

### 7.2 Copy モードと Reference モード

データ取り込み時に必ずどちらかを選択します（FR-DAT-002）。

この選択は Project 作成時の保存場所とは別です。Copy / Reference は取り込む元データの保持方法を決め、Project 作業フォルダーはアプリが管理する database、artifact、cache の配置先を決めます。選択 UI の形式や既定値は未確定です。

| モード | 概要 | 注意点 |
|---|---|---|
| **Copy モード** | 元画像を Project 作業領域へ複製して使用する | 元ファイルと同等の容量が Project 領域に追加されます |
| **Reference モード** | 元ファイルを複製せず、絶対パスと内容ハッシュを参照する | ファイルが移動・変更・削除された場合は再リンクが必要です |

*（実装完了後に、モードの選択手順・容量計算の表示・再リンクの手順を記載予定）*

**Reference モードの注意事項（FR-DAT-012、FR-DAT-013）：**

- 参照元ファイルが継続してアクセスできない場合は再リンクを求めます。
- Training Run 開始直前と学習中に全ファイルのハッシュ検証を行います。変更・消失が 1 件でもあれば Run を開始しないか安全に停止します。

### 7.3 入力データの権利確認

Project での初回データ取り込み時に、入力画像・ラベル・アノテーションを利用・学習する権利を有することを確認する画面が表示されます（FR-LIC-009）。

- アプリは法的権利を自動保証しません。
- 確認日時は Project に記録されます。

補助候補（Model Suggestion）は、既存モデルが生成したラベル名・分類ラベル・矩形の候補です。**人が確認するまで Ground Truth にはなりません。**

### 補助に使用するモデル

- 補助候補は Ground Truth（確定済みアノテーション）と異なる色・線種・バッジで表示されます（FR-AST-009）。

各候補を個別に次のいずれかで処理します（FR-AST-010）。

- **承認** — 候補を draft アノテーションにコピーする（画像全体の「確認済み」にはなりません）
- **編集して承認** — 内容を修正してから draft アノテーションにコピーする
- **却下** — 候補を使用しない

**全候補の処理と画像単位の確定操作を完了した画像だけが「確認済み」になります。**

### 自動承認はありません

高スコアでも自動承認・一括承認は提供しません（FR-AST-011）。補助候補の承認のみでは「確認済み」にならず、見逃しがないかをユーザーが確認する操作が必要です。

Inference Profile は Project ごとの推論設定です。端末診断、データ取り込み、Label Schema とは別の lifecycle を持ちます。保存場所、既定値、編集画面名は実装・実測後に確定します。

### 性能について

- 推奨ハードウェアと承認済み軽量モデルでは、30 分連続試験で FR-INF-010 / NFR-PERF-004 の service time、capture-to-display p95、10 Hz 全フレーム処理、drop 0 を満たすことが**出荷条件**です。
- 端末が 100 ms を超える場合は最新フレーム優先で継続し、実 FPS・レイテンシ・drop 数・性能警告を表示します（FR-INF-011）。

### 学習と推論のリソース競合

同じアクセラレーターで学習が実行中の場合、推論開始前に警告が表示されます。学習の中断または CPU での推論のいずれかを選択できます（FR-INF-019）。

### 学習が失敗する場合

考えられる原因と対処を案内する設計です（FR-TRN-020）。表示文言と実際の recovery は未検証です。

- ディスク容量不足：空き容量の確保

- キャッシュや失敗 Run の一時 checkpoint を選択削除する設計です。操作と回復容量は未検証です。

### 用語集

要求定義 §5 に掲載された主な用語を以下に転記します。詳細は [`docs/requirement-definition.md`](requirement-definition.md) §5 を参照してください。

| 用語 | 定義 |
|---|---|
| Project | CV タスク・データセット履歴・学習 Run・モデル版・推論設定をまとめる最上位単位。 |
| タスク種別 | `Image Classification` または `Object Detection`。初回学習後は変更不可。 |
| Dataset Revision | 取り込んだ画像・ラベル・分割・ファイルハッシュを固定した不変のデータセット版。 |
| Training Run | 1 回の AutoML 実行。複数 Trial・ログ・評価・状態を持つ。 |
| Trial | 1 組のモデル候補・ハイパーパラメーターによる学習試行。 |
| Model Version | 成功した Training Run から生成される不変の学習済みモデル一式。 |
| Curated Base Weight | 初回学習に用いる、製品側でライセンスと由来を承認した基盤重み。 |
| Model Suggestion | 既存モデルが生成したラベル名・分類ラベル・矩形等の候補。人が承認するまでは Ground Truth ではない。 |
| Ground Truth | ユーザーが確認し、教師データとして確定した分類ラベルまたは矩形アノテーション。 |
| Copy モード | 元画像を Project 作業領域へ複製して使用する方式。 |
| Reference モード | 元ファイルを複製せず、絶対パスと内容ハッシュを保持して参照する方式。 |
| AutoML | 候補モデル選択・Fine-Tuning・ハイパーパラメーター探索・枝刈り・最良モデル決定を自動実行するローカル処理。Cloud 製品名を意味しない。 |
| Annotation Assist Model | 補助候補生成のため、製品側で checkpoint・由来・ライセンス・性能を承認してインストーラーに同梱した既存モデル。 |
