## 1. 対応範囲

> **この節は実装完了後に実測内容で更新します。現時点は要求定義からの抜粋です。**

AutoVision Studio は次の処理をローカル端末内で完結します。

- **画像分類（Image Classification）** — 画像 1 枚に対し、定義したクラスのうち正確に 1 つを割り当てます（single-label multi-class）。
- **物体検出（Object Detection）** — 画像内の物体に axis-aligned の矩形（bounding box）とクラスを割り当てます（multi-class）。

### MVP に含まれるもの

以下は実装対象の機能です（要求定義 §3.1 参照）。

- 複数 Project の作成・管理
- ローカルファイル・フォルダーからの教師データ取り込み
- 画面上での分類ラベルおよび検出矩形の作成・編集・確認
- 既存モデルによる補助候補の生成と人による確認
- バックグラウンド自動学習（AutoML・ハイパーパラメーター探索）
- 学習履歴・モデル版管理・評価レポート
- 既存モデル版を起点とした追加学習
- PC / Mac カメラへのリアルタイム推論
- 完全オフライン動作
- Windows x64 および macOS Apple Silicon (arm64) 用の自己完結型インストーラー

### MVP に含まれないもの

以下は Version 1 の対象外です（要求定義 §3.2 参照）。

- Cloud サービスとの連携、外部ストレージ、テレメトリ
- ユーザーアカウント・組織管理・共同編集
- 手動でのハイパーパラメーター入力
- 動画ファイル・ネットワークカメラ・RTSP ストリーム
- セグメンテーション・姿勢推定・OCR・生成 AI
- 分散学習・複数 PC をまたぐ学習

## 4. Project の管理

> **本節は、Project 一覧画面（UI-02）および Project 作成・設定画面（UI-03）の実装・検証が完了したときに更新します。**
>
> 要求の詳細は要求定義 §8.2（FR-PRJ-001〜010）を参照してください。

Project は AutoVision Studio の最上位管理単位です。1 つの Project には、タスク種別（画像分類 または 物体検出）・教師データ・学習履歴・モデル版・推論設定が含まれます。

### 主な操作（実装完了後に手順を記載予定）

- **Project の作成** — 名前・説明・タスク種別・作業フォルダーを指定します。
- **Project 一覧** — タスク種別・最終更新日時・学習状態・推論対象モデル版・使用容量を確認できます。
- **Project の設定更新** — 名前・説明・作業フォルダー・既定の推論設定を変更できます。
- **Project の削除** — 削除前に、Annotation Workspace・Model Suggestion・Dataset Revision・Training Run・Model Version・レポート・キャッシュの件数と容量が表示されます。Reference モードの参照元ファイルは削除されません（FR-PRJ-007/008）。

### 制約事項

- タスク種別は初回 Training Run 作成後に変更できません。異なるタスク種別が必要な場合は、新しい Project を作成してください（FR-PRJ-006）。
- Project は内部的に UUID で一意に識別されます。同名Projectを許可するかを含む最終的な入力規則は、実装・検証後に本節へ記載します（FR-PRJ-003）。
- 学習実行中に Project を切り替えても、バックグラウンド学習は継続されます（FR-PRJ-009）。

## 5. データ取り込み

> **本節は、データ取り込み画面（UI-04）の実装・検証が完了したときに更新します。**
>
> 要求の詳細は要求定義 §8.3（FR-DAT-001〜016）を参照してください。

### 5.1 対応形式

*（実装完了後に実際の検証方法と制限を記載予定）*

**対応画像形式：** JPEG、PNG、WebP、BMP、TIFF

- 拡張子だけでなく画像の実体を検証します。
- アニメーション画像は非対応です（先頭フレームのみの暗黙利用は行いません）。
- EXIF Orientation を反映した向きで表示・学習します。元ファイルは変更しません。

**アノテーション形式：**

- 画像分類：未ラベル画像、`ルート/クラス名/画像` のフォルダー構造、`path,label` を持つ UTF-8 CSV
- 物体検出：未アノテーション画像、または COCO JSON（画像・カテゴリ・bounding box）と対応する画像ルート

取り込み時の検証エラーが 1 件でもある場合は、学習を自動開始しません（FR-DAT-008）。

### 5.2 Copy モードと Reference モード

データ取り込み時に必ずどちらかを選択します（FR-DAT-002）。

| モード | 概要 | 注意点 |
|---|---|---|
| **Copy モード** | 元画像を Project 作業領域へ複製して使用する | 元ファイルと同等の容量が Project 領域に追加されます |
| **Reference モード** | 元ファイルを複製せず、絶対パスと内容ハッシュを参照する | ファイルが移動・変更・削除された場合は再リンクが必要です |

*（実装完了後に、モードの選択手順・容量計算の表示・再リンクの手順を記載予定）*

**Reference モードの注意事項（FR-DAT-012、FR-DAT-013）：**

- 参照元ファイルが継続してアクセスできない場合は再リンクを求めます。
- Training Run 開始直前と学習中に全ファイルのハッシュ検証を行います。変更・消失が 1 件でもあれば Run を開始しないか安全に停止します。

### 5.3 入力データの権利確認

Project での初回データ取り込み時に、入力画像・ラベル・アノテーションを利用・学習する権利を有することを確認する画面が表示されます（FR-LIC-009）。

- アプリは法的権利を自動保証しません。
- 確認日時は Project に記録されます。

## 6. Label Schema の設定

> **本節は、Label Schema 画面（UI-09）の実装・検証が完了したときに更新します。**
>
> 要求の詳細は要求定義 §8.3.1（FR-ANN-003〜004、FR-ANN-012）を参照してください。

Label Schema は、Project で使用するクラスの分類体系です。

### Schema に含まれる情報

- クラス ID（UUID）・表示名・色・説明
- 補助モデル用の model alias（任意）
- 正常例・境界例・反例（annotation instruction として常時参照可能）
- 物体検出の場合は、occlusion・画像端の切れ・極小物体・曖昧な境界に関する Project 固有の方針（FR-ANN-207）

### 主な操作（実装完了後に手順を記載予定）

- クラスの作成・名前変更・色変更・説明編集
- クラスの統合（複数クラスを 1 つに結合）
- 未使用クラスの削除

### 制約事項

- クラス名は Unicode を許可しますが、空白のみの名前・同一 Project 内で正規化後に重複する名前は拒否されます（FR-ANN-004）。
- **初回 Model Version の学習開始後は Label Schema がロックされます**（FR-ANN-012）。クラスの追加・削除・統合・意味変更が必要な場合は、新しい Project での初回学習が必要です。

## 7. 画像分類のアノテーション

> **本節は、教師データ作成画面（UI-10）の分類機能の実装・検証が完了したときに更新します。**
>
> 要求の詳細は要求定義 §8.3.2（FR-ANN-101〜107）および §8.3.1（FR-ANN-001〜014）を参照してください。

画像分類では、各画像に Label Schema 内のクラスを正確に **1 つだけ** 割り当てます。

### 主な操作（実装完了後に手順を記載予定）

- **一覧表示（Gallery view）** — 複数画像を選択して同じクラスを一括適用する
- **詳細表示（Single view）** — 1 画像を拡大確認してクラスを適用する
- クラスの割り当て・置換・解除・除外（除外理由を任意で記録可能）
- 編集の自動保存・undo / redo

### 各画像の状態

取り込み後の画像は次の状態で管理されます（FR-ANN-005）。

| 状態 | 説明 |
|---|---|
| 未着手 | ラベルも補助候補もない |
| 補助候補あり | 補助モデルが候補を生成済み、未確認 |
| 編集中 | ユーザーが編集を開始している |
| 確認済み | ユーザーが明示的に確定操作を行った |
| 除外 | 学習・評価 split に含めない |

**「確認済み」の画像のみが教師データになります。** 未確認の画像は Dataset Revision に含まれません（FR-ANN-011）。

### 確認時の検証

Dataset Revision 確定前に次の項目が検証されます（FR-ANN-011）。

- 0 件クラスまたは複数クラスが割り当てられた画像（エラー）
- Label Schema 外のクラス（エラー）
- 未処理の補助候補
- クラスごとの件数と偏り

エラーが 1 件でもある場合は確定できません。

## 8. 物体検出のアノテーション（矩形）

> **本節は、教師データ作成画面（UI-10）の検出機能の実装・検証が完了したときに更新します。**
>
> 要求の詳細は要求定義 §8.3.3（FR-ANN-201〜209）を参照してください。

物体検出では、1 画像に axis-aligned の矩形（bounding box）を 0 個以上作成し、各矩形に Label Schema 内のクラスを正確に **1 つ** 割り当てます。

### 主な操作（実装完了後に手順を記載予定）

- drag による矩形の作成
- 矩形の選択・移動・辺 / 角によるサイズ変更・クラス変更・複製・削除・全選択
- region list と画像上の矩形の相互選択
- zoom / pan（元画像のピクセル座標は変化しません）
- keyboard shortcut による操作・undo / redo

### 制約事項（FR-ANN-205）

- 矩形は画像の境界内に clamp されます。
- 幅・高さが 0、NaN、負値、画像外のみの矩形は拒否されます。

### 対象物がない画像

対象物が存在しない画像は「対象物なし」と明示確認できます（FR-ANN-206）。未着手とは区別され、negative sample として Dataset Revision に含まれます。

### COCO フォーマットの取り込みと編集

取り込んだ COCO の bounding box と category を同じエディターで修正できます（FR-ANN-209）。元の COCO フォーマット（`[x, y, width, height]`）への lossless な変換が行われ、provenance（`import-unmodified` / `import-edited`）が記録されます。

## 9. 補助候補と人による確認

> **本節は、補助ジョブ画面（UI-11）と補助候補機能（Phase H）の実装・検証が完了したときに更新します。**
>
> 要求の詳細は要求定義 §8.3.4（FR-AST-001〜020）を参照してください。

補助候補（Model Suggestion）は、既存モデルが生成したラベル名・分類ラベル・矩形の候補です。**人が確認するまで Ground Truth にはなりません。**

### 補助に使用するモデル

- 同一 Project に成功済み Model Version がある場合、最新成功版が既定で選択されます（FR-AST-002）。
- 成功版がない場合は、インストーラーに同梱した Annotation Assist Model が使用されます。
- 使用するモデルのバージョン・チェックポイントハッシュ・しきい値ポリシーは常時表示されます。

**補助 Assist Model についての重要事項（FR-AST-004）：**
インストーラーに同梱するモデルは、ライセンス・データ由来・用途・品質の審査を通過したものだけです。現時点で同梱を承認済みの補助モデルはありません。審査前のモデルを同梱した状態では本機能は出荷されません。

### 補助候補の表示

- 補助候補は Ground Truth（確定済みアノテーション）と異なる色・線種・バッジで表示されます（FR-AST-009）。
- モデルスコアがある場合は「モデルスコア」として表示します（「正解確率」とは表示しません、FR-AST-012）。

### ユーザーの操作（実装完了後に手順を記載予定）

各候補を個別に次のいずれかで処理します（FR-AST-010）。

- **承認** — 候補を draft アノテーションにコピーする（画像全体の「確認済み」にはなりません）
- **編集して承認** — 内容を修正してから draft アノテーションにコピーする
- **却下** — 候補を使用しない

**全候補の処理と画像単位の確定操作を完了した画像だけが「確認済み」になります。**

### 自動承認はありません

高スコアでも自動承認・一括承認は提供しません（FR-AST-011）。補助候補の承認のみでは「確認済み」にならず、見逃しがないかをユーザーが確認する操作が必要です。

## 10. 学習・ジョブ・追加学習

> **本節は、Training Run 画面（UI-05）および学習機能（Phase I）の実装・検証が完了したときに更新します。**
>
> 要求の詳細は要求定義 §8.4（FR-TRN-001〜021）および §8.5（FR-MOD-001〜005）を参照してください。

### 学習の開始

Dataset Revision を確定すると、追加のハイパーパラメーター入力を求めずに Training Run が自動登録されます（FR-TRN-001）。学習は UI とは別のプロセスで実行され、学習中も Project の閲覧・画面遷移が可能です（FR-TRN-002）。

**ハイパーパラメーターはユーザーが指定しません。** 内部の探索空間・選択理由・各 Trial の実値はレポートで確認できます（FR-TRN-007）。

### Training Run の状態

| 状態 | 説明 |
|---|---|
| Queued | 実行待ち（FIFO） |
| Preparing | 準備中 |
| Running | 学習中 |
| Exporting | ONNX 変換中 |
| Evaluating | 評価中 |
| Succeeded | 完了（Model Version が作成されます） |
| Failed | 失敗（ログ・Trial は保持） |
| Cancelled | キャンセル済み（再開不可） |
| Interrupted | 中断（条件一致時に再開可能） |

Model Version は `Succeeded` のときのみ作成されます。

### 実行の制約

- 1 台の端末で同時に実行される Training Run は原則 1 件で、他は FIFO Queue に置かれます（FR-TRN-010）。
- Queued 状態の Run を削除できます。
- 実行中の Run をキャンセルできます。キャンセル後は再開できません（FR-TRN-013）。
- アプリまたは OS の異常終了後、条件が一致する場合のみ中断 Run を再開できます（FR-TRN-014）。

### 学習時間について

学習時間はデータ件数・画像解像度・クラス数・ハードウェアに依存します（要求定義 §6.2）。固定の学習時間は保証されません。ノート PC で長時間学習する場合は電源接続と十分な冷却を推奨します。

### 追加学習

既存の成功済み Model Version を起点として追加学習できます（FR-TRN-004、FR-TRN-005）。

*（実装完了後に、Base Model Version の選択手順・制約を記載予定）*

**制約事項（FR-TRN-021）：** 追加学習で使用する Dataset Revision のクラス集合は、Base Model Version と完全に一致している必要があります。クラスの追加・削除・名前変更がある場合は、新しい Project での初回学習が必要です。

## 11. 結果・レポート

> **本節は、結果・レポート画面（UI-06）の実装・検証が完了したときに更新します。**
>
> 要求の詳細は要求定義 §8.6（FR-REP-001〜012）を参照してください。

Training Run および Model Version ごとに、概要・データ・評価・Trial・画像・環境・ライセンスのタブで結果を確認できます（FR-REP-001）。

### 確認できる指標（実装完了後に詳細を記載予定）

**画像分類（FR-REP-002）：**
- accuracy、balanced accuracy、macro / micro precision・recall・F1
- クラス別指標・loss 曲線・混同行列

**物体検出（FR-REP-003）：**
- mAP@[0.50:0.95]、AP50、AP75
- クラス別 AP / precision / recall・PR 曲線・loss 曲線

**Trial 一覧（FR-REP-004）：**
- 全 Trial の状態・開始 / 終了時刻・枝刈り理由・全ハイパーパラメーター・中間指標・最終指標

**画像ギャラリー（FR-REP-005〜007）：**
- 元画像のサムネイル一覧と詳細表示
- 分類：正解ラベル・予測上位候補・信頼度
- 検出：ground truth と予測 box の色分け・クラス・信頼度・IoU・FP / FN

### 信頼度スコアについての注意

「信頼度」はモデルのスコアであり、正解確率を意味しません。スコアの意味・範囲・しきい値はモデル manifest から参照できます（FR-AST-012）。

### Reference モードで元画像が見つからない場合

レポート自体は開き、該当画像を「参照切れ」と表示して再リンクを提供します（FR-REP-008）。

## 12. カメラ推論とプライバシー

> **本節は、推論画面（UI-07）の実装・検証が完了したときに更新します。**
>
> 要求の詳細は要求定義 §8.7（FR-INF-001〜019）を参照してください。

### プライバシーに関する重要事項

- カメラフレームおよび推論結果は**既定でディスクに保存されません**（FR-INF-017）。
- ログにも画像の内容は保存されません（FR-INF-017）。
- カメラフレームは端末外に送信されません（FR-SEC-001）。
- 音声は利用しません。マイク権限は要求しません（FR-INF-007）。

### カメラ権限の要求タイミング

カメラ権限は、**ユーザーが推論開始操作をした時だけ**要求します（FR-INF-003）。起動時・Project 閲覧時・インストール時には要求しません（FR-INS-014）。

OS の権限要求の前に、利用目的・保存有無・停止方法をアプリ内で説明し、ユーザーの明示同意を得ます（FR-INF-004）。

### 主な操作（実装完了後に手順を記載予定）

- 推論対象モデル版の選択（同一 Project の成功済み版から）
- カメラの選択（複数ある場合）
- 推論の開始・停止
- 信頼度しきい値・表示設定の保存（Inference Profile、FR-INF-014）

### 性能について

- 推奨ハードウェアと承認済み軽量モデルでは、30 分連続試験で FR-INF-010 / NFR-PERF-004 の service time、capture-to-display p95、10 Hz 全フレーム処理、drop 0 を満たすことが**出荷条件**です。
- 端末が 100 ms を超える場合は最新フレーム優先で継続し、実 FPS・レイテンシ・drop 数・性能警告を表示します（FR-INF-011）。

### 学習と推論のリソース競合

同じアクセラレーターで学習が実行中の場合、推論開始前に警告が表示されます。学習の中断または CPU での推論のいずれかを選択できます（FR-INF-019）。

### ストレージの確認

Project・Dataset Revision・Training Run・Model Version・キャッシュごとの使用容量を確認できます（NFR-STO-002）。

*（実装完了後に、各項目の確認方法・削除方法を記載予定）*

## 14. トラブルシューティング

> **本節は、各機能の実装・動作検証が完了したときに、実際に発生した事象をもとに更新します。現時点は構成のみです。**
>
> 要求の詳細は要求定義 §8.1（FR-SYS）、§8.3（FR-DAT）、§8.9（FR-SEC）を参照してください。

*（実装完了後に各項目の確認手順・対処方法を記載予定）*

### カメラ権限が拒否された場合

- **Windows：** システム設定（Privacy & security > Camera）を開く導線と再試行が表示されます（FR-INF-005）。
- **macOS：** `notDetermined / granted / denied / restricted` の各状態が処理されます（FR-INF-006）。

### Reference モードでファイルが見つからない場合

- 再リンクを求めるダイアログが表示されます（FR-DAT-012）。
- Training Run 実行中にハッシュ不一致が検出された場合は、Run が安全に停止されます（FR-DAT-013）。

### 学習が失敗する場合

考えられる原因と対処の案内が表示されます（FR-TRN-020）。

- 対応していない演算：軽量な候補へのフォールバック
- GPU メモリ不足（OOM）：batch size の縮小・CPU フォールバック
- ディスク容量不足：空き容量の確保
- 画像読込失敗：対象ファイルと修正方法の表示

### ディスク容量が不足している場合

- データ取り込み前に、元データ・予測生成物・一時領域・安全余裕（20%）を含む必要容量を計算します（NFR-STO-001）。容量不足の場合は開始しません。
- キャッシュや失敗 Run の一時チェックポイントを削除して容量を確保できます。

### 診断ログの出力

ローカル診断 export はユーザーの操作時だけ生成され、含有項目が事前に表示されます（NFR-SEC-004）。ログには画像本体は含まれません（FR-SEC-010）。

## 付録

### 用語集

要求定義 §5 に掲載された主な用語を以下に転記します。詳細は [`docs/requirement-definition.md`](requirement-definition.md) §5 を参照してください。

| 用語 | 定義 |
|---|---|
| Project | CV タスク・データセット履歴・学習 Run・モデル版・推論設定をまとめる最上位単位。 |
| タスク種別 | `Image Classification` または `Object Detection`。初回学習後は変更不可。 |
| Dataset Revision | 取り込んだ画像・ラベル・分割・ファイルハッシュを固定した不変のデータセット版。 |
| Training Run | 1 回の AutoML 実行。複数 Trial・ログ・評価・状態を持つ。 |
| Trial | 1 組のモデル候補・ハイパーパラメーターによる学習試行。 |
| Model Version | 成功した Training Run から生成される不変の学習済みモデル一式。 |
| Curated Base Weight | 初回学習に用いる、製品側でライセンスと由来を承認した基盤重み。 |
| Model Suggestion | 既存モデルが生成したラベル名・分類ラベル・矩形等の候補。人が承認するまでは Ground Truth ではない。 |
| Ground Truth | ユーザーが確認し、教師データとして確定した分類ラベルまたは矩形アノテーション。 |
| Copy モード | 元画像を Project 作業領域へ複製して使用する方式。 |
| Reference モード | 元ファイルを複製せず、絶対パスと内容ハッシュを保持して参照する方式。 |
| AutoML | 候補モデル選択・Fine-Tuning・ハイパーパラメーター探索・枝刈り・最良モデル決定を自動実行するローカル処理。Cloud 製品名を意味しない。 |
| Annotation Assist Model | 補助候補生成のため、製品側で checkpoint・由来・ライセンス・性能を承認してインストーラーに同梱した既存モデル。 |
