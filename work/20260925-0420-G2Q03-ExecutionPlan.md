## 1. 閾値の方針 A の定義（測定の前に固定する）

所有者が選んだのは A の一文（coverage ≥ 0.5 を満たす閾値のうち、一致率 / F1 が最大のもの）である。下のうち、候補の範囲・同率時の選び方・中点・「一致率」の解釈は、A を一意に計算するために実装担当が測定の前に固定する規約で、所有者の回答には含まれない（所有者の判断の記録にもそう書く）。

共通:

- 候補の閾値: torch の score で、判定に使う score の値（重複を除く）。分類は各 item の top-1 の score、検出は全 item の全 patch の box の score。境界は `score >= 閾値`（manifest schema の `confidenceThreshold` の説明「Inclusive lower bound (score >= threshold)」: `resources/models/manifest.schema.json:609-611`）。
- 制約: coverage（提案があった item の割合）が 0.5 以上（gold set 計画 §3。G2D-07C / 07D で承認）。
- 選び方: 制約を満たす候補のうち、下の指標が最大のもの。同じ値が複数ある場合は coverage が大きい方、それも同じなら閾値が小さい方を選ぶ（人の確認の対象になる提案を減らさない側。候補の score は互いに異なるため、これで 1 つに決まる）。
- 記録する閾値: 選んだ score と、候補の中でそれより小さい次の score（無い場合は 0）の中点。torch での提案の集合は選んだ候補と同じで、backend 間の score の小さな差で境界の item が入れ替わりにくくする。
- 再計算できる記録: 出力 JSON の `threshold_selection` に、選んだ score（`selected_score`）と、全候補の `score`・`coverage`・`metric`（制約を満たさない候補は `null`）を score の降順で記録する。main4 の verify は `work/20260925-0420-check-selection.py` でこれを再計算する。
- 制約を満たす候補が無い場合は `verdict: FAIL`。
- model 単体の評価基準（§8.12 の「計画で固定した model 単体の評価基準」）は、上の制約を満たす閾値があること、とする。承認された計画に精度の下限は無いため、精度の下限は置かない（観測値として記録する）。

分類（G2Q-03C、SigLIP）:

- 提案: item ごとに score が最大の label（top-1）。その score が閾値以上なら提案あり。
- 指標「一致率」: 提案があった item のうち、提案の label が gold label と一致した割合。提案が無い item を不一致に数える形（全 item の正解率）は、閾値を下げるほど値が下がらないため常に最小の閾値が選ばれ、coverage の制約が意味を持たない。このため、提案した item の中の割合と解釈する（本計画の解釈。所有者の判断の記録にも書く）。
- prompt 形式: `This is a photo of {label}.`（`{label}` は label 名の `_` を空白に置き換えたもの）。出典: Hugging Face transformers v5.17.0 の SigLIP の文書の Notes「To get the same results as the Pipeline, a prompt template of "This is a photo of {label}." should be passed to the processor.」（https://huggingface.co/docs/transformers/model_doc/siglip 。spike の venv の transformers は 5.17.0: `docs/model-governance/siglip-base-patch16-224-adoption.md` §13）。
- backend の比較: fp32 ONNX（CPU・DirectML）と torch の score の最大差が既存の許容差 `1.0e-04`（`spikes/models/detection.py:55`）以下。

検出（G2Q-03D、OWL-ViT）:

- 提案: patch ごとの box で、score が閾値以上のもの。1 box 以上ある item を「提案あり」とする。
- 指標: gold set 計画 §5 と同じ形の F1（同じ item の中で、提案の box と gold box を IoU の大きい順に 1 対 1 で対応させ、IoU 0.5 以上を一致とし、全 20 item の box をまとめる）。
- prompt 形式: `a photo of a {label}`（`{label}` は同上）。出典: spike の prompt（`docs/model-governance/owlvit-base-patch32-adoption.md` §9 の「spike は `a photo of a <label>`」）。text query は gold set の class（`wheat_head`）だけ。
- 境界: `score >= 閾値`（schema）。transformers の `post_process_object_detection` は `score > threshold` のため、製品の後処理は `>=` で実装する必要がある、と記録する。
- 検出単位の parity: 記録する閾値で、torch・ORT CPU・DirectML の検出を `detection_checkpoint_parity.compare` で比べる（既存の許容差）。torch の検出が 0 件なら `FAIL`。生出力は既存の `rtol 1e-3`・`atol 1e-4`。

seed: `{"torch": 20260922}`（spike の値 `spikes/models/detection.py:44`。採用記録 §9）。
