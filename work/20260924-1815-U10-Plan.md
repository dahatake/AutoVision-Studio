# U-10 #2: 削除 preview の古い応答を使わない guard（UIR-025 残条件 #2）

## 1. 範囲と出典

- 利用者の判断: 「U-10: #2 だけを範囲に入れる」（`work/20260924-1815-OwnerRulingExecutionPlan.md` §1）。U-10 の定義は `work/202609240830-RemainTaskExecutionPlan.md` 393 行（範囲に入れる場合は AUD-01 の記録の根拠行を入力にして、1 ノード 1 成果物の別計画を作る）。
- 残条件 #2 の要求: 「実previewの全対象件数・容量・所有/Reference境界を接続。失敗・Project切替後の古いpreviewを使用せず」（`docs/implementation-plan.md` 867 行、`docs/ui-ux-execution.md` 447 行）。
- AUD-01 の判定（`work/20260924-0300-UirStatusRedetermination.md` 45 行）: UI 表示と失敗時の clear はあるが、preview の応答の後の再検証は API の同一性だけで、Project 切替後の古い preview を使わない guard と test が確認できない。
- 現状の code: `openDeletePreview`（`src/renderer/layout/AppShell.tsx` 351〜365 行）は `await api.deletePreview` の後に `apiContext.current.active` と `apiContext.current.api !== api` だけを確かめる（359 行）。応答の前に別の Project の削除確認を始めた場合、または一覧・設定・作成・作業画面へ移った場合でも、古い応答の preview を dialog に出す。表示中の dialog（469〜471 行）は、画面の移動では閉じない。
- 範囲外: #4（CORE-13A の受入）、#7（Gate 3 の再判定）、#6・#8・#9、実削除（`runDelete`）の挙動、`DeleteProjectDialog.tsx`、Main と IPC。UIR-025 の親を完了と記録しない（#4・#6〜#9 が残る）。

## 2. 設計

`AppShell.tsx` の既存の世代番号の方式（`selectionGeneration`、318・326 行）に合わせ、削除の preview だけの世代番号 `deletionGeneration`（`useRef(0)`）を 1 つ加える。

1. `openDeletePreview` は開始時に `const ticket = ++deletionGeneration.current` とし、応答の後に `deletionGeneration.current !== ticket` なら何もしない（古い応答を捨てる）。
2. 画面の移動（`invalidateSelection` と `selectProject` の開始。`showList`・`startCreate`・`openSettings`・`closeSettings`・「選択をやめる」は `invalidateSelection` を通る）で `deletionGeneration.current++` とし、表示中の preview を閉じる（`preview: null`、`busy: false`。`receipt` と実削除の途中の状態（`busy` かつ `preview` あり）は変えない）。2 か所で同じ処理のため、component 内の関数 `closeDeletePreview()` にまとめる。
3. 新しい抽象・設定・log は加えない。
