## 2. 作業者の手順（G2Q-04C〜05D で使う）

1. gold set 計画（`spikes/models/assist-goldset-plan-classification.md` または `-detection.md`）の item 一覧を、記録の前に作業者へ渡す。item の順番と件数は記録中に変えない。
2. 作業者は製品の editor を通常どおり使う。観測者（または作業者自身）は外部のストップウォッチで、item ごとに作業の開始と終了を測り、差を秒で `seconds` に書く。開始は item が editor に表示された時点（assisted session では C7 の提案を待つ時間も含む）、終了は次の item へ移った時点（最後の item は作業を終えた時点）とし、両方の session で同じ定義を使う。
3. 同じ作業中に、item ごとの `outcome` を 1 つ書く。manual-only session は全 item が `manual`（`proposed: false`）。assisted session は、C7 の提案があった item が `accept` / `edit` / `reject`（`proposed: true`）、提案がなかった item が `manual`（`proposed: false`）。
4. assisted session では、承認済み C7 の実出力と `item_id`（`sourceImageKey`）を結び付けた sidecar を作業と同時に残す。import provenance だけを C7 の提案の証跡にしない（同調査結果の候補 1 の方法）。sidecar は session file と同じ directory の `<session file の stem>.sidecar.jsonl` で、`proposed: true` の item ごとに 1 行（`{"item_id": "...", "output": <その item に対する C7 の実出力>}`）を持つ。
5. 1 item 1 行の JSON Lines にする（`assist_benchmark.py` 20〜24 行の形式）:

   ```json
   {"item_id": "...", "proposed": true, "outcome": "accept", "seconds": 4.5}
   ```

6. 保存先は `vendor/models/_spike/assist/<session file>`（`manual-classification.jsonl`・`manual-detection.jsonl`・`assisted-classification.jsonl`・`assisted-detection.jsonl`）。同じ directory に受け渡しメモ `<session file>.meta.txt`（`recorded_at: <記録日時>`・`recorder: <記録者>`・`settings: <使った設定>` の各 1 行。assisted session では sidecar の SHA-256 を `sidecar_sha256: <小文字の 16 進>` の 1 行で加える）を置く（Gate 2 計画 §8.14、452 行）。

## 3. 値を補完しない規則

- `seconds` と `outcome` は生成・推定・補完しない。測り忘れた item と、sidecar と照合できない assisted item は未取得として扱い、その session は記録し直す。
- 現在の harness は、session の中の `item_id` の重複を拒否し（`assist_benchmark.py` 70〜73 行）、assisted と manual-only の `item_id` の集合が一致することを要求する（同 273〜281 行）が、gold set の item との照合はしない。そのため、記録者は受け渡しの前に次の 2 つの検査を実行し、どちらかが exit 0 でない session は記録し直す（`<task>` は `classification` または `detection`、`<session>` は `manual` または `assisted`）。
  - gold set との照合（全 session）: session の `item_id` が重複なく `expected_item_count` 件あり、gold set manifest の `items[].item_id` の集合と一致する。manual-only session は `proposed: true` の item を持たない。受け渡しメモは `recorded_at:`・`recorder:`・`settings:` の行に空でない値を持つ。

    ```powershell
    & vendor\models\_spike\venv\Scripts\python.exe -c "import json,re,sys,pathlib; b=pathlib.Path(r'vendor\models\_spike\assist'); g=json.load(open(b/sys.argv[1],encoding='utf-8')); gi=[i['item_id'] for i in g['items']]; p=b/sys.argv[2]; r=[json.loads(l) for l in open(p,encoding='utf-8') if l.strip()]; s=[x['item_id'] for x in r]; t=(b/(p.name+'.meta.txt')).read_text(encoding='utf-8'); ok=len(s)==len(set(s))==len(gi)==g['expected_item_count'] and set(s)==set(gi) and (p.name.startswith('assisted-') or not any(x['proposed'] for x in r)) and all(re.search('^'+k+r': \S',t,re.M) for k in ('recorded_at','recorder','settings')); sys.exit(0 if ok else 1)" goldset-<task>.json <session>-<task>.jsonl; exit $LASTEXITCODE
    ```

  - sidecar との照合（assisted session）: sidecar の全行が null でない `output` を持ち、`item_id` が重複せず、その集合が session の `proposed: true` の item の集合と一致し、sidecar の SHA-256 が受け渡しメモの `sidecar_sha256:` の値と一致する。

    ```powershell
    & vendor\models\_spike\venv\Scripts\python.exe -c "import hashlib,json,re,sys,pathlib; b=pathlib.Path(r'vendor\models\_spike\assist'); p=b/sys.argv[1]; q=b/(p.stem+'.sidecar.jsonl'); s=[json.loads(l) for l in open(p,encoding='utf-8') if l.strip()]; r=[json.loads(l) for l in open(q,encoding='utf-8') if l.strip()]; c=[x['item_id'] for x in r]; m=re.findall(r'^sidecar_sha256: ([0-9a-f]{64})$',(b/(p.name+'.meta.txt')).read_text(encoding='utf-8'),re.M); sys.exit(0 if all(x.get('output') is not None for x in r) and len(c)==len(set(c)) and set(c)=={x['item_id'] for x in s if x['proposed']} and m==[hashlib.sha256(q.read_bytes()).hexdigest()] else 1)" assisted-<task>.jsonl; exit $LASTEXITCODE
    ```
- editor の provenance と target の履歴は、入力済みの `outcome` の監査材料に限り、item の `outcome` へ集約しない（同調査結果の候補 1）。
